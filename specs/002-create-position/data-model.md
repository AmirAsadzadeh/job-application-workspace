# Data Model: Create a Job Position

## Positions Document

`data/positions.json` contains one versioned document.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `version` | integer | Yes | Must equal `3` after a successful version 3 write. |
| `positions` | Position[] | Yes | May be empty; IDs are unique; file order is list order. |

Version 1 and version 2 documents remain readable for migration. Reads do not rewrite
them. The next successful create or update writes the complete normalized version 3
document atomically.

## Position

| Field | Type | Required | Row-visible | Rules |
|-------|------|----------|-------------|-------|
| `id` | string | Yes | No | Non-empty, unique, generated by the service. |
| `company` | Company | Yes | Yes | Name required; at most one logo source. |
| `title` | string | Yes | Yes | Trimmed and non-empty. |
| `status` | PositionStatus | Yes | Yes | New positions start as `draft`. |
| `workMode` | WorkMode | Yes | Yes | Required approved value. |
| `employmentType` | EmploymentType | Yes | No | Defaults to `full_time`. |
| `seniority` | Seniority | Yes | Yes | Required approved value. |
| `departmentId` | string or null | Yes | No | Must identify a reference department when set. |
| `teamId` | string or null | Yes | No | Must belong to `departmentId` when set. |
| `locationId` | string or null | Yes | No | Must identify a reference location when set. |
| `hiringManager` | HiringManager | Yes | No | All blank or all complete. |
| `salary` | Salary or null | Yes | No | Complete valid group or null. |
| `description` | RichTextDocument | Yes | No | May be visually empty; includes job requirements. |
| `jobPlatformLinks` | JobPlatformLink[] | Yes | No | Ordered complete pairs; may be empty. |
| `careerPageUrl` | string or null | Yes | No | Absolute HTTP/HTTPS URL when set. |
| `createdAt` | ISO date-time | Yes | No | Generated by the service. |
| `updatedAt` | ISO date-time | Yes | Yes | Equals `createdAt` on creation. |

Version 3 has no `requirements` field. A strict schema rejects it after migration.

### Enumerations

| Type | Stored values |
|------|---------------|
| PositionStatus | `draft`, `open`, `interviewing`, `on_hold`, `closed` |
| WorkMode | `remote`, `hybrid`, `onsite` |
| EmploymentType | `full_time`, `part_time`, `contract`, `internship` |
| Seniority | `Intern`, `Entry`, `Associate`, `Mid-level`, `Senior`, `Staff`, `Lead`, `Manager`, `Director` |

## Company

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `name` | string | Yes | Trimmed and non-empty; supplies fallback initial and accessible name. |
| `logoPath` | string or null | Yes | `/company-logos/<generated-or-bundled-name>` when set. |
| `logoUrl` | string or null | Yes | Absolute HTTP/HTTPS URL when set. |

`logoPath` and `logoUrl` cannot both be non-null. Both null selects the company-letter
fallback. An image load error also selects the fallback without changing the stored value.

## Hiring Manager

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `name` | string | Yes | Blank only when the whole group is blank. |
| `phone` | string | Yes | Preserved as text; blank only when the whole group is blank. |
| `position` | string | Yes | Blank only when the whole group is blank. |

## Salary

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `min` | number | Yes | Finite and non-negative. |
| `max` | number | Yes | Finite, non-negative, and not below `min`. |
| `currency` | string | Yes | Three uppercase ASCII letters. |

Salary is either a complete object or null. Partially entered salary values are invalid.

## Job Platform Link

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `platformName` | string | Yes | Trimmed and non-empty. |
| `url` | string | Yes | Absolute HTTP/HTTPS URL. |

Blank draft rows are discarded before validation. Partially populated rows are retained in
the form and block submission.

## Rich Text Document

The existing restricted JSON structure remains unchanged: a `doc` root containing
paragraphs, level 1-3 headings, bullet lists, numbered lists, list items, text, hard breaks,
bold, italic, and absolute HTTP/HTTPS link marks. Unsupported content is not persisted.

The stable empty value is one empty paragraph.

## Create Position Input

| Field | Required from user | Normalized result |
|-------|--------------------|-------------------|
| `companyName` | Yes | `company.name` |
| `companyLogo` | No | Null, remote `logoUrl`, or generated local `logoPath` |
| `title` | Yes | `position.title` |
| `workMode` | Yes | Approved WorkMode |
| `seniority` | Yes | Approved Seniority |
| `employmentType` | No | Approved value; defaults to `full_time` |
| Assignment values | No | Valid IDs or null |
| Hiring-manager values | No | All-blank or complete object |
| Salary values | No | Null or complete Salary |
| Publication values | No | Complete links and optional career URL |
| `description` | No | Rich document; defaults to stable empty value |

The client cannot submit persisted identity, status, or timestamps.

### Company Logo Input

The create request uses a discriminated value:

| Kind | Fields | Rules |
|------|--------|-------|
| `none` | `kind` | Produces null path and URL. |
| `remote` | `kind`, `url` | URL is absolute HTTP/HTTPS; bytes are never fetched by the service. |
| `upload` | `kind`, `fileName`, `mediaType`, `dataBase64` | Decoded data is at most 2 MB and matches PNG, JPEG, or SVG. |

The service generates the upload filename and never uses `fileName` as a filesystem path.

## Relationships

- A Positions Document contains zero or more Positions in list order.
- A Position has exactly one Company and Rich Text Document.
- A Position has zero or one selected logo source, Hiring Manager value group, Salary,
  Department, Team, Location, and career-page URL.
- A Position has zero or more ordered Job Platform Links.
- A Team is valid only within its selected Department.
- A created Position is prepended to the Positions Document.

## Migration Rules

1. Parse version 1 plain descriptions or version 2 rich descriptions.
2. Normalize company identity to include `logoUrl: null` while preserving `logoPath`.
3. Preserve every existing position field except the removed `requirements` property.
4. If `requirements` contains non-empty entries, append a level-2 `Requirements` heading
   and one bullet-list item per entry, retaining order and text.
5. Validate the resulting version 3 document and all reference relationships.
6. Keep the normalized value in memory on read; write it only as part of a separately
   successful create or update.

Migration preserves position order. A new create is prepended only after all legacy
positions have been normalized.

## State Transitions

| From | Event | To |
|------|-------|----|
| Untouched form | Any field changes | Dirty form |
| Dirty form | Invalid save | Dirty form with field guidance |
| Dirty form | Valid save begins | Saving; save disabled |
| Saving | Service failure | Dirty form with retained values and error |
| Saving | Service success | Created Draft position; navigate to list |
| Dirty form | Confirm discard | List without a created record |
| Dirty form | Cancel discard | Dirty form remains open |

Status transitions after creation are outside this journey.
